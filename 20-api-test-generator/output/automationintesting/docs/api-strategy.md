## Auth Strategy

```
POST /api/auth/login
Body: {"username": "admin", "password": "password"}
Response: sets cookie `token=abc123...`

All subsequent auth requests: include Cookie header
```

**Fixture approach:**
- `auth_token` fixture: login at start of test session, store cookie
- Pass cookie to all authenticated requests
- Validate token before test if session expired

## Implementation Waves

### Wave 1 — Smoke + Auth (Week 1)
- Auth: login, validate, logout, expired token
- Room: GET all, GET by ID, POST, PUT, DELETE
- Booking: GET (no auth → 401), POST public booking

### Wave 2 — Full CRUD + Contract (Week 2)
- Booking: full CRUD with auth
- Message: POST, GET, DELETE
- Contract: schema validation per endpoint
- Negative: missing fields, invalid types, not found
- **Output**: +25 tests

### Wave 3 — Security + Performance (Week 3)
- Security: BOLA (access other user's booking), broken auth, mass assignment
- Performance: response time budgets per endpoint
- Report: admin report endpoint
- **Output**: +20 tests
