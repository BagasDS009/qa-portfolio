## SQE Recommendations

> The following are engineering recommendations — NOT documented requirements.

1. **Request a decision table** from PM showing all combinations of (device × location × attempts) → risk level. This is the most critical missing piece.

2. **Define numeric thresholds** before development begins:
   - "Too many attempts" = exactly N attempts within T minutes
   - "Unusual location" = distance > X km from last N logins

3. **Add a "Medium Risk" tier** — binary (Low/High) will generate excessive OTPs for legitimate users traveling or using new browsers.

4. **Define OTP lifecycle** completely:
   - Format: 6-digit numeric
   - Expiry: 5 minutes
   - Resend: allowed after 60s, max 3 resends
   - After 3 failures: temporary lockout (15 min), not permanent

5. **Define fail-safe mode** — if the risk-check microservice is unavailable:
   - Fail-open (allow login) → availability over security
   - Fail-closed (block login) → security over availability
   - For fintech, recommend fail-closed with fast fallback

6. **Plan phased rollout** to avoid RISK-007 (all devices "new" on Day 1):
   - Week 1: Shadow mode (log risk scores, don't enforce OTP)
   - Week 2: Enforce for new accounts only
   - Week 3: Enforce for all, with "trust this device" option

7. **Define compliance requirements** — fintech likely subject to PCI-DSS, SOC 2, or local regulations that mandate specific log retention and access controls.
